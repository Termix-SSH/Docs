# Translations

Never hard code text. Put every string your plugin shows in `locales/en.json`:

```json
{
  "tab": { "title": "Hello", "empty": "No notes yet." },
  "permissions": {
    "use": {
      "title": "Use Hello",
      "description": "Open the Hello tab and keep notes in it."
    }
  }
}
```

Keys in the manifest (`titleKey`, `labelKey` and so on) and calls to `t()` look up this file. Each plugin has its own namespace, so your `tab.title` never clashes with another plugin's.

```tsx
const { t } = useTranslation();
return <p>{t("tab.empty")}</p>;
```

A key you don't define falls back to Termix's shared strings, like `common.save`.

Outside a component, use `app.t("tab.title")`.

## Other languages

Official plugins are translated automatically when they are released. A community plugin ships its own translations, or none at all. Any language or string you don't translate shows in English.

To add a language, copy `locales/en.json` to `locales/translated/<file>.json` with the same keys and translate the values. Keep `{{placeholders}}` as they are.

## Plurals

Pass `count` and add a key per plural form. English has two:

```json
{ "hosts_one": "{{count}} host", "hosts_other": "{{count}} hosts" }
```

```tsx
t("hosts", { count: 3 });
```

Some languages have more forms. Russian needs `_one`, `_few`, `_many` and `_other`, and Arabic adds `_zero` and `_two`. Use the forms that language uses, not the English ones. See the [CLDR plural rules](https://www.unicode.org/cldr/charts/latest/supplemental/language_plural_rules.html).
