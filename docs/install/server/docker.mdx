# Docker

The simplest way to get Termix server up and running is with Docker.

Termix is light. It idles at about 118 MB of RAM, and 1 core with 1 GB covers most setups. See [Benchmarks](/benchmarks) for measured usage and how much to allocate for larger fleets.

## Installation

<Tabs defaultValue="guacd">
  <TabItem value="guacd" label="Docker Compose with guacd (Recommended)">

```yaml
services:
  termix:
    image: ghcr.io/lukegus/termix:latest
    container_name: termix
    restart: unless-stopped
    ports:
      - '8080:8080'
    volumes:
      - termix-data:/app/data
    environment:
      PORT: '8080'
    depends_on:
      - guacd
    networks:
      - termix-net

  guacd:
    image: guacamole/guacd:1.6.0
    container_name: guacd
    restart: unless-stopped
    ports:
      - "4822:4822"
    networks:
      - termix-net

volumes:
  termix-data:
    driver: local

networks:
  termix-net:
    driver: bridge
```

To start the containers, run:

```bash
docker-compose up -d
```

## Docker Hub Mirror

As an alternative to GHCR, you can also use the Docker Hub mirror by replacing `ghcr.io/lukegus/termix:latest` with `bugattiguy527/termix:latest` in any of the configurations above.

## Specific Version

By default, `:latest` always points to the newest release. If you want to pin a specific version instead, replace `:latest` in your docker run/compose with one of these tag formats, swapping in the version you want:

- `:x.x.x`, for example `:2.4.0`
- `:release-x.x.x`, for example `:release-2.4.0`

Both formats point to the same image for a given version, so use whichever you prefer. See a list of all versions [here](https://github.com/Termix-SSH/Termix/releases), or browse every published tag on [GitHub](https://github.com/users/LukeGus/packages/container/package/termix).

## Beta Builds

:::info Want to try what's coming next?
Betas are early builds of the next Termix version. They come out on Tuesdays and Fridays when there is something new, and your feedback is what makes the stable release better.
:::

To join, replace `:latest` with `:beta` in any of the configurations above and restart the container:

```
ghcr.io/termix-ssh/termix:beta
```

`:beta` always follows the newest beta. Each beta also has its own tag, like `:26.11.0-beta.2`, if you want to stay on one. Desktop betas are on the [releases page](https://github.com/Termix-SSH/Termix/releases), marked as pre-releases.

In Termix, an admin can open **Settings > Updates** and turn on **Termix betas** to be told about new betas. The same page lists the newest stable and beta releases.

:::warning
Betas can have bugs, and a beta can change the database. Keep a backup of the `termix-data` volume before you switch. To go back, switch to `:latest` once a stable release newer than your beta is out.
:::

### Plugin betas

Each plugin can use betas on its own, so you can try a fix for one plugin without changing anything else. Open the plugin in **Plugins** and press **Try beta**, or turn on **Beta versions** on its page. **Settings > Updates** lists every plugin on a beta and can move them all at once.

Turning **Beta versions** off keeps the beta you have until a newer stable release of that plugin comes out, then it updates as normal.

### Feedback

Use **Send beta feedback** in **Settings > Updates**, on a plugin's page, or in the command palette. It opens a short form with your versions already filled in. You can also talk about betas in the [Discord](https://discord.gg/jVQGdvHDrf) server.

## Database

The compose files above use SQLite, which is the default and needs no setup. The database lives in the `termix-data` volume.

If you would rather keep the data in PostgreSQL or MySQL, add two variables to the `termix` service:

```yaml
environment:
  PORT: '8080'
  DATABASE_DIALECT: postgres
  DATABASE_URL: postgres://termix:yourpassword@db:5432/termix
```

Keep the `termix-data` volume either way. Termix still uses it for encryption keys, SSL certificates, and session recordings.

See [Database](/setup/database) for a full compose example with a Postgres service, MySQL setup, and TLS options.
