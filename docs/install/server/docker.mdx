# Docker

Docker is the easy way to run Termix. The image has the web UI, the server and the most used plugins in it. Pick a smaller or bigger image with a [tag](#tags).

## Tags

| Tag | What you get |
| --- | --- |
| `latest` | The newest stable release with the standard plugins. |
| `26.10.0` | One exact version. Use this to stay on a version until you choose to update. |
| `beta` | The newest beta. See [betas](/configure/betas). |
| `latest-minimal` | The newest stable release with only the look plugins. |
| `latest-full` | The newest stable release with every official plugin. |

Add `-minimal` or `-full` to any tag to pick a plugin set, for example `26.10.0-full` or `beta-minimal`. A tag with no suffix is the standard set.

## Plugin sets

Every image has the same server. Only the plugins inside it differ.

| Set | What is in it | Use it when |
| --- | --- | --- |
| Minimal | The default look: the Classic layout and the Classic themes. | You want the smallest image and will install only what you need from the Plugins tab. It needs internet access to install anything. |
| Standard | The look plugins plus the most used ones: SSH terminal, file manager, Docker, host metrics, snippets, tunnels, remote desktop, workspaces, alerts, TOTP, passkeys, SSO, sync, telemetry, serial, host status, import and export, credential tools. | Most installs. It works offline and has what most people want. |
| Full | Every official plugin. | You want everything ready, or the server has no internet access. |

Plugins that are not in your set are still in the registry. Install them any time from the Plugins tab, see [managing plugins](/guide/plugins). Plugins you install this way are saved in `/app/data`, so they stay when you update the image.

If you move an existing install to a smaller set, Termix downloads the plugins you had turned on from the registry the first time it starts, so nothing goes missing. This needs internet access. If the registry can't be reached, those plugins stay off and Termix tries again on the next start. Plugins you had turned off are not downloaded. Install them from the Plugins tab if you want them. Their data stays in `/app/data` either way.

## Your data

Everything Termix keeps is in `/app/data`: the database, its keys, plugins, uploads and recordings. Keep that volume. If you lose it, you lose your hosts and credentials.

If you use a bind mount instead of a named volume, make sure the folder is owned by the user the container runs as. Set `PUID` and `PGID` to match:

```yaml
    environment:
      PUID: "1000"
      PGID: "1000"
    volumes:
      - ./termix-data:/app/data
```

See [backup and restore](/install/backup) for how to back it up.

## Ports

| Port | What it is |
| --- | --- |
| `8080` | The web UI and API. Change it with `PORT`. |
| `8443` | HTTPS, when `ENABLE_SSL` is on. Change it with `SSL_PORT`. |

If you run your own guacd for remote desktop instead, see [External guacd](/plugins/remote-desktop#external-guacd-optional). Don't publish its port.

## Update

```bash
docker compose pull
docker compose up -d
```

Back up `/app/data` first. See [updating](/install/updating).
